# Getting Started
## Risk Management Process

| Step                   | Explanation                                                                                                                                                                               |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Identifying the Risk` | Identifying risks the business is exposed to, such as legal, environmental, market, regulatory, and other types of risks.                                                                 |
| `Analyze the Risk`     | Analyzing the risks to determine their impact and probability. The risks should be mapped to the organization's various policies, procedures, and business processes.                     |
| `Evaluate the Risk`    | Evaluating, ranking, and prioritizing risks. Then, the organization must decide to accept (unavoidable), avoid (change plans), control (mitigate), or transfer risk (insure).             |
| `Dealing with Risk`    | Eliminating or containing the risks as best as possible. This is handled by interfacing directly with the stakeholders for the system or process that the risk is associated with.        |
| `Monitoring Risk`      | All risks must be constantly monitored. Risks should be constantly monitored for any situational changes that could change their impact score, `i.e., from low to medium or high impact`. |
## Red Team vs Blue Team
<span style="color:#fe1616">Red teamers</span> usually play an adversary role in breaking into the organization to identify any potential weaknesses real attackers may utilize to break the organization's defenses. The most common task on the red teaming side is penetration testing, social engineering, and other similar offensive techniques.

On the other hand, the <span style="color:#009dff">blue team</span> makes up the majority of infosec jobs. It is responsible for strengthening the organization's defenses by analyzing the risks, coming up with policies, responding to threats and incidents, and effectively using security tools and other similar tasks.

A [virtual private network (VPN)](https://en.wikipedia.org/wiki/Virtual_private_network) allows us to connect to a private (internal) network and access hosts and resources as if we were directly connected to the target private network. It is a secured communications channel over shared public networks to connect to a private network (i.e., an employee remotely connecting to their company's corporate network from their home). VPNs provide a degree of privacy and security by encrypting communications over the channel to prevent eavesdropping and access to data traversing the channel.

## Common Terms
Shell - program that takes input from the user via the keyboard and passes these commands to the operating system to perform a specific function.

|**Shell Type** | **Description**|
|`Reverse shell` | Initiates a connection back to a "listener" on our attack box.
|`Bind shell` | "Binds" to a specific port on the target host and waits for a connection from our attack box.
|`Web shell` | Runs operating system commands via the web browser, typically not interactive or semi-interactive. It can also be used to run single commands (i.e., leveraging a file upload vulnerability and uploading a `PHP` script to run a single command.

Ports are virtual points where network connections begin and end. They are software-based and managed by the host operating system. Ports are associated with a specific process or service and allow computers to differentiate between different traffic types (SSH traffic flows to a different port than web requests to access a website even though the access requests are sent over the same network connection).

Web server is an application that runs on the back-end server, which handles all of the `HTTP` traffic from the client-side browser, routes it to the requests destination pages, and finally responds to the client-side browser.

# Service Scanning 

|**Concept / Command**|**Description**|
|---|---|
|**Core Concepts**||
|Service|Application running on a computer that performs a useful function for other users/computers|
|Server|Specialized machine that hosts services|
|Focus|Services that are misconfigured or vulnerable → coerce into unintended actions (e.g., execute commands)|
|Port range|1 – 65,535; well-known = 1 – 1,023; port 0 = reserved "wild card"|
|Default Nmap scan|TCP, top 1,000 most common ports|
|**Nmap**||
|`nmap 10.129.42.253`|Basic scan (top 1,000 ports)|
|`nmap -sV -sC -p- 10.129.42.253`|`-sV` version scan, `-sC` default scripts, `-p-` all 65,535 TCP ports|
|`nmap --script <name> -p<port> <host>`|Run a specific Nmap script|
|`nmap -sV --script=banner <target>`|Banner grabbing via Nmap|
|`nmap -A -p445 <target>`|Aggressive scan (OS, version, scripts, traceroute)|
|**Banner Grabbing**||
|`nc -nv 10.129.42.253 21`|Manual banner grab via Netcat (→ `220 (vsFTPd 3.0.3)`)|
|**FTP (21)**||
|`ftp -p 10.129.42.253`|Connect to FTP (login `anonymous` if allowed)|
|`ls` / `cd pub` / `get login.txt` / `exit`|List, change dir, download file, quit|
|Finding|`login.txt` → `admin:ftp@dmin123` (credentials)|
|**SMB (139/445)**||
|`nmap --script smb-os-discovery.nse -p445 <target>`|Discover SMB OS info|
|`smbclient -N -L \\\\10.129.42.253`|List shares (no password prompt)|
|`smbclient -U bob \\\\10.129.42.253\\users`|Connect with credentials → `get passwords.txt`|
|**SNMP**||
|`snmpwalk -v 2c -c public <target> 1.3.6.1.2.1.1.5.0`|Query system name via default community string `public`|
|`onesixtyone -c dict.txt <target>`|Brute force community strings|
|**Key Takeaways**||
|Workflow|Basic scan → advanced scan (`-sV -sC -p-`) → banner grab → service enumeration (FTP/SMB/SNMP)|
|Goal|Find credentials, sensitive files, and vulnerabilities to further access|

# Web Enumeration 

|**Command / Concept**|**Description**|
|---|---|
|**Core Concepts**||
|Web Enumeration|Critical when web servers (80/443) host web apps → large attack surface, high-value target|
|Goal|Uncover hidden files/directories, subdomains, sensitive data → access or RCE|
|**Gobuster — Directory/File Enumeration**||
|`gobuster dir -u http://10.10.10.121/ -w /usr/share/seclists/Discovery/Web-Content/common.txt`|Brute-force directories/files (`dir` mode)|
|Status 200|Request successful|
|Status 403|Forbidden to access|
|Status 301|Redirect (not a failure)|
|Finding|`/wordpress` (301) → CMS in setup mode → potential RCE|
|**Gobuster — DNS Subdomain Enumeration**||
|`git clone https://github.com/danielmiessler/SecLists`|Clone SecLists wordlists|
|`sudo apt install seclists -y`|Install SecLists via apt|
|Add `1.1.1.1` to `/etc/resolv.conf`|Set DNS server|
|`gobuster dns -d inlanefreight.com -w /usr/share/SecLists/Discovery/DNS/namelist.txt`|Enumerate subdomains (`dns` mode)|
|Finding|`blog`, `customer`, `my`, `ns1`, `ns2`, `ns3`.inlanefreight.com|
|**Banner Grabbing / Web Server Headers**||
|`curl -IL https://www.inlanefreight.com`|Retrieve server header info (`-I` headers, `-L` follow redirects)|
|Reveals|Application framework, auth options, missing security options, misconfigurations|
|EyeWitness|Screenshot target web apps, fingerprint, identify default credentials|
|**WhatWeb**||
|`whatweb 10.10.10.121`|Extract web server versions, frameworks, apps|
|`whatweb --no-errors 10.10.10.0/24`|Automate enumeration across a network|
|**Certificates**||
|View SSL/TLS cert (HTTPS)|Reveals email address, company name → useful for phishing (if in scope)|
|**Robots.txt**||
|`/robots.txt`|Instructs crawlers which resources can/cannot be indexed; may reveal private files & admin pages|
|Finding|Disallows `/private`, `/uploaded_files` → `/private` = HTB admin login page|
|**Source Code**||
|`CTRL + U`|View page source; may reveal developer comments with test account credentials|
|**Key Takeaways**||
|Workflow|Directory brute-force → DNS subdomain enum → headers/banner → WhatWeb → certificates → robots.txt → source code|
|Goal|Find hidden functionality, sensitive data, credentials, and vulnerabilities|
