# Footprinting

Enumeration -  information gathering using active (scans) and passive (use of third-party providers) methods.
Our goal is not to get at the systems but to find all the ways to get there.
This methodology is nested in 6 layers and represents, metaphorically speaking, boundaries that we try to pass with the enumeration process. The whole enumeration process is divided into three different levels:

| `Infrastructure-based enumeration` | `Host-based enumeration` | `OS-based enumeration` |
| ---------------------------------- | ------------------------ | ---------------------- |

![](https://i.imgur.com/CTEhrmI.png)


| **Layer**                | **Description**                                                                                        | **Information Categories**                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| `1. Internet Presence`   | Identification of internet presence and externally accessible infrastructure.                          | Domains, Subdomains, vHosts, ASN, Netblocks, IP Addresses, Cloud Instances, Security Measures      |
| `2. Gateway`             | Identify the possible security measures to protect the company's external and internal infrastructure. | Firewalls, DMZ, IPS/IDS, EDR, Proxies, NAC, Network Segmentation, VPN, Cloudflare                  |
| `3. Accessible Services` | Identify accessible interfaces and services that are hosted externally or internally.                  | Service Type, Functionality, Configuration, Port, Version, Interface                               |
| `4. Processes`           | Identify the internal processes, sources, and destinations associated with the services.               | PID, Processed Data, Tasks, Source, Destination                                                    |
| `5. Privileges`          | Identification of the internal permissions and privileges to the accessible services.                  | Groups, Users, Permissions, Restrictions, Environment                                              |
| `6. OS Setup`            | Identification of the internal components and systems setup.                                           | OS Type, Patch Level, Network config, OS Environment, Configuration files, sensitive private files |

Layer 1 - The goal of this layer is to identify all possible target systems and interfaces that can be tested.
Layer 2 - The goal is to understand what we are dealing with and what we have to watch out for.
Layer 3 - This layer aims to understand the reason and functionality of the target system and gain the necessary knowledge to communicate with it and exploit it for our purposes effectively.
Layer 4 - The goal here is to understand these factors and identify the dependencies between them.
Layer 5 - It is crucial to identify these and understand what is and is not possible with these privileges.
Layer 6 - The goal here is to see how the administrators manage the systems and what sensitive internal information we can glean from them.

## NFS

|**Command / Option**|**Description**|
|---|---|
|**Core Concepts**||
|NFS|Network File System (Sun Microsystems) — access file systems over network as if local; used between Linux/Unix systems|

## SMTP

|**Command / Option**|**Description**|
|---|---|
|**Core Concepts**||
|SMTP|Simple Mail Transfer Protocol — sends emails in IP networks; client-server based; can be between client↔server or server↔server|
|Default port|TCP 25; newer servers use TCP 587 (STARTTLS, authenticated users)|
|Encrypted port|TCP 465 (SSL/TLS)|
|Unencrypted|SMTP transmits all commands/data/auth info in plaintext; use SSL/TLS to protect|

# Remote Management Protocols
## Linux Remote Management Protocols

|**Command / Option**|**Description**|
|---|---|
|**Core Concepts**||
|Goal|Remotely manage Linux servers; save time; same working environment|
|Risk|Misconfigurations can lead to quick unauthorized access|
|**SSH**||
|SSH|Secure Shell — encrypted direct connection over insecure network; standard port TCP 22|
|Protocols|SSH-1 (vulnerable to MITM) vs SSH-2 (advanced: encryption, speed, stability, security)|
|OpenSSH|Open-source fork of original commercial SSH server; native on Linux/MacOS; available on Windows|
|Authentication methods|Password, Public-key, Host-based, Keyboard, Challenge-response, GSSAPI|
|**Public Key Authentication**||
|Step 1|Server sends public host key to client → client verifies server identity|
|Step 2|Client proves access authorization using public/private key pair|
|Private key|Created for user's own computer; secured with passphrase (longer than typical password); stored exclusively on own computer|
|Public key|Stored on server; server creates cryptographic problem → client decrypts with private key → sends solution|
|Session|Enter passphrase once to connect to any number of servers|
|**Default Configuration**||
|`cat /etc/ssh/sshd_config \| grep -v "#" \| sed -r '/^\s*$/d'`|View active SSH config|
|`Include /etc/ssh/sshd_config.d/*.conf`|Include additional config files|
|`ChallengeResponseAuthentication no`|Disable challenge-response auth|
|`UsePAM yes`|Use PAM|
|`X11Forwarding yes`|Allow X11 forwarding (CVE in OpenSSH 7.2p1, 2016)|
|`PrintMotd no`|Don't print MOTD|
|`AcceptEnv LANG LC_*`|Accept environment variables|
|`Subsystem sftp /usr/lib/openssh/sftp-server`|SFTP subsystem|
|**Dangerous Settings**||
|`PasswordAuthentication yes`|Allows password-based authentication (brute-forceable)|
|`PermitEmptyPasswords yes`|Allows empty passwords|
|`PermitRootLogin yes`|Allows login as root|
|`Protocol 1`|Uses outdated encryption|
|`X11Forwarding yes`|Allows X11 forwarding for GUI apps|
|`AllowTcpForwarding yes`|Allows TCP port forwarding|
|`PermitTunnel`|Allows tunneling|
|`DebianBanner yes`|Displays specific banner on login|
|**Footprinting — ssh-audit**||
|`git clone https://github.com/jtesta/ssh-audit.git && cd ssh-audit`|Clone ssh-audit|
|`./ssh-audit.py 10.129.14.132`|Fingerprint SSH server; shows banner, software version, key exchange/host-key algorithms|
|Findings|Banner (SSH-2.0-OpenSSH_8.2p1 Ubuntu), weak elliptic curves, weak hashing algorithms|
|**SSH Client Verbose / Auth Method**||
|`ssh -v cry0l1t3@10.129.14.132`|Verbose connection — shows available auth methods|
|`ssh -v cry0l1t3@10.129.14.132 -o PreferredAuthentications=password`|Force password authentication (for brute-force)|
|Banner examples|`SSH-1.99-OpenSSH_3.9p1` (supports SSH-1 & SSH-2); `SSH-2.0-OpenSSH_8.2p1` (SSH-2 only)|
|**Rsync**||
|Rsync|Fast/efficient local & remote file copying; delta-transfer algorithm; port 873; can use SSH|
|`sudo nmap -sV -p 873 127.0.0.1`|Scan Rsync (protocol version 31)|
|`nc -nv 127.0.0.1 873`|Probe service → list accessible shares (e.g., `dev`)|
|`rsync -av --list-only rsync://127.0.0.1/dev`|Enumerate open share contents|
|`rsync -av rsync://127.0.0.1/dev`|Sync all files to attack host|
|`-e ssh` / `-e "ssh -p2222"`|Use SSH for transfer (non-standard port)|
|**R-Services**||
|R-Services|Suite for remote access/commands between Unix hosts over TCP/IP; unencrypted (MITM risk)|
|Ports|512, 513, 514|
|Common OS|Solaris, HP-UX, AIX|
|**R-Commands**||
|`rcp`|Remote copy — port 514/TCP (rshd); bidirectional file copy|
|`rsh`|Remote shell — port 514/TCP (rshd); shell without login; relies on trusted entries|
|`rexec`|Remote execution — port 512/TCP (rexecd); run commands; username/password auth (unencrypted)|
|`rlogin`|Remote login — port 513/TCP (rlogind); login to Unix-like hosts|
|Other|`rstat`, `ruptime`, `rwho`, `rusers`|
|**Trusted Relationships**||
|`/etc/hosts.equiv`|Global trusted hosts list; auto-grant access without further auth|
|`.rhosts`|Per-user trusted configuration|
|Syntax|`<username> <ip address>` or `<username> <hostname>`; `+` = wildcard|
|Example|`+ 10.0.17.10` allows any external user via that host|
|**Footprinting — Nmap**||
|`sudo nmap -sV -p 512,513,514 10.0.17.2`|Scan r-services ports|
|**Logging in Using Rlogin**||
|`rlogin 10.0.17.2 -l htb-student`|Log in via rlogin (exploiting `.rhosts` misconfiguration)|
|**Enumerating Users**||
|`rwho`|List all interactive sessions on local network (UDP 513)|
|`rusers -al 10.0.17.5`|Detailed logged-in users (username, hostname, TTY, login time, idle time, remote host)|
|**Final Thoughts**||
|Approach|Probe remote management services for info; try weak/default credentials and password reuse|

## Windows Remote Management Protocols

|**Command / Option**|**Description**|
|---|---|
|**Core Concepts**||
|Remote management|Enabled by default starting with Windows Server 2016|
|Main components|RDP, WinRM, WMI|
|**RDP**||
|RDP|Remote Desktop Protocol — GUI remote access to Windows; application layer; TCP port 3389 (also UDP 3389 for remote admin)|
|Requirements|Both network firewall and server firewall must allow connections; NAT requires public IP + port forwarding|
|Encryption|TLS/SSL since Windows Vista; many systems still accept RDP Security (inadequate); certificates self-signed by default → cannot distinguish genuine from forged|

|`--packet-trace`|Track packets; RDP cookie `mstshash=nmap` can be detected by EDR/threat hunters → lockout risk|
|`rdp-sec-check.pl`|Cisco CX Security Labs Perl script; unauthenticated identification of RDP security settings|

|WinRM|Windows Remote Management — command-line based; uses SOAP; must be explicitly enabled/configured starting with Windows 10|
|Ports|TCP 5985 (HTTP), TCP 5986 (HTTPS)|
|WinRS|Windows Remote Shell — execute arbitrary commands on remote system; included on Windows 7 by default|

|WMI|Windows Management Instrumentation — Microsoft's implementation/extension of CIM (WBEM); read/write access to almost all Windows settings; most critical admin interface|
